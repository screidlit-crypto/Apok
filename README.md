# Сервер мультиплеера «Зона Апокалипсиса»

Это небольшой WebSocket-сервер-посредник для HTML-игры. Он создаёт комнаты по коду и пересылает сообщения между двумя игроками. Игровой мир пока рассчитывает хост — это промежуточный этап миграции, а не полноценный авторитетный игровой сервер.

## Развёртывание на Render

1. Создай GitHub-репозиторий и загрузи в него три файла из этой папки: `server.js`, `package.json`, `README.md`.
2. На Render создай **New → Web Service** и подключи репозиторий.
3. Выбери Runtime **Node**, Build Command `npm install`, Start Command `npm start`.
4. После публикации открой выданный Render URL, например `https://имя-сервиса.onrender.com/health`. Должен появиться JSON с `"ok":true`.
5. В игре используй адрес того же сервиса, но с `wss://`, например `wss://имя-сервиса.onrender.com`.
6. Оба игрока должны открыть одну и ту же версию `Зона_Апокалипсиса_WebSocket.html`, вставить этот `wss://` адрес в поле сервера, затем хост нажимает «Создать комнату», а второй игрок вводит код и нажимает «Подключиться».

Render может усыплять бесплатные сервисы после периода бездействия, поэтому первое подключение иногда занимает время. Для локального теста: установи Node.js 18+, выполни `npm install`, затем `npm start`; в поле игры укажи `ws://localhost:3000` (это сработает только у игрока на том же компьютере; для второго компьютера нужен доступный извне сервер и `wss://`).

## Важно

- Сервер рассчитан на две стороны: хоста и одного гостя.
- Не размещай на нём секретные данные: он только пересылает игровые пакеты.
- Этот переход меняет транспорт с PeerJS на WebSocket, но сам по себе не делает всю симуляцию сервер-авторитетной и не гарантирует устранение всех лагов. Для следующего этапа нужно оптимизировать и разделить пакеты состояния мира, а затем переносить критичную логику на сервер.
